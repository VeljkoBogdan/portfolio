ReFactory: Expert

ReFactory is the largest project, and the longest one that I've worked on. I have semi-consistently been working on it for the past 3 years (at the time of writing - November 2026).

It is a tech modpack for Minecraft, and a labor of love, which almost 2k people have played. The project page can be viewed here

A large portion of the modifications that I've done was through KubeJS. KubeJS is a mod that allows scripting various aspects of the game and other mods through JavaScript. It uses a modified version of Rhino that translates JS to Java. This allows me to edit game and mod events, add or remove items, recipes, machines, etc.

The modpack also heavily relies on GregTechCEu's API, which I've needed to learn through their docs and source code for difficult edits.

Although KubeJS offers a lot of tools, some modifications I couldn't do through it, especially the ones that rely on GregTech's source code instead of their built-in KubeJS integration API. That's when I've decided to make my own mod - ReFactory Core. It allows custom machines, advanced machine logic, advanced recipe logic, custom icon sets, custom sounds, etc.

Voxel Game using OpenGL

I wanted to challenge myself by learning graphics programming using OpenGL, since I couldn't understand what was happening under the hood of the GL abstraction libraries like raylib and libgdx.

This was written in C++ and other functional libraries like glad, glfw and FastNoise2. It is my most difficult project to date (November 2026).

The most difficult thing to implement, yet the most rewarding, was batch rendering (indirect buffer). Since I did not want to make just another Minecraft clone, and the sound of a truly infinite, procedurally generated world excites me, I decided to make this project have infinite generation in all three directions (x, y and z). In contrast, Minecraft has only 2 truly infinite directions, x and z, with the y going from -64 to around 320. Minecraft divides the world into a 2D matrix of 16x16 chunks, since the Y is constant. In this game though, Y is not constant, so the world is divided into a 3D array of 16x16x16 chunks. At 16 render distance, Minecraft's world has 16x16=256 chunks (x^2), and can get away with having a draw call for every single one. In this game, 16 render distance means 16x16x16=4096 chunks (x^3), that means I couldn't get away with having a draw call for every single one. Luckily, OpenGL 4.3 introduced indirect buffer rendering, which allows me to send all the chunks and a transformation matrix for them to the shader, which offsets all the work from the CPU to the GPU, which can process it in parallel. This comes at a drawback - MacOS dropped support of OpenGL since 4.1, so my program cannot be run on Mac PCs.

Apart from that, I've also implemented Fast Approximate Anti-Aliasing (FXAA), Raycasts, Fast noise generation using SIMD instructions (FastNoise2 library), day-night cycle, multithreaded chunk loading, unloading, and remeshing, and several other smaller implementations.

GregCrops

GregCrops is a mod I've made designed for ReFactory: Expert, but that can also be used as standalone.

It's an addon to the mod GregTechCEu, and adds customizable crops of different GregTech materials (e.g. salt, aluminium, copper). It was made with ReFactory in mind as the modpack was already floral-themed

The seeds are registered using another mod or KubeJS, and then they get generated upon game start. Each seed generates alongside a crop. Once fully grown it can be harvested. The seed material and the dropped item can be customized. The seeds and crops get automatically colored depending on the seed material.

The mod relies heavily on GTCEu's API and source code to work, and still has some ironing out to do.
